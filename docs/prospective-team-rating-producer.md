# Prospective Team Rating Producer

## Status

This change adds the operational producer required to create Team Rating-only
`P0` before a future formal map's prediction cutoff. It is not a historical
backtest and it never turns reconstructed predictions into prospective ones.

Every accepted prediction has the following ledger state:

```text
availability_mode = prospective
team_rating_runs.status = trained
team_rating_predictions.status = predicted
team_rating_predictions.eventual_radiant_win = NULL
```

The producer does not write a Prematch production probability, change
Calibration or Deployment, or invoke an order path.

## Frozen configuration and seed

The producer never selects Team Rating hyperparameters per target. A collection
window starts from one immutable `prospective_team_rating_seeds` row containing:

- the accepted `TeamRatingConfig` and its content hash;
- `seed_as_of` and `seed_training_cutoff`;
- the availability-ordered authority manifest and content hash;
- the chronologically ordered rating replay and content hash;
- the full Team Rating state and state hash;
- the content-addressed seed artifact and `frozen_at`.

The seed may contain historical state, but it creates no historical
`availability_mode=prospective` predictions. `frozen_at` must precede every
future target cutoff that uses it. Creating the seed is an explicit one-time
operation; the CLI does not search a parameter grid or infer a configuration.

## Causal production path

For each formal target, the producer reads `match_id`, `series_id`, event,
Radiant/Dire team identities, scheduled start, and any roster identity available
at collection time. The scheduled start is the current explicit
`prediction_cutoff`, identified by:

```text
cutoff_source = prospective_scheduled_start
```

It always starts from the frozen seed authority and reads the complete set of
post-seed formal results whose authoritative `first_usable_at` is:

```text
seed_as_of < result_usable_at <= producer observed_at < prediction_cutoff
```

It combines that set with the seed source manifest and rebuilds the complete
Team Rating state from empty for every P0. This deliberately avoids snapshot
incrementality: a late historical backfill is inserted at its real match time
without skipping it, changing timestamps, or moving a rating clock backward.

Authority eligibility remains deterministically ordered by:

1. authoritative result availability time;
2. map start time;
3. `match_id`.

Only the resulting cutoff-eligible set is reordered for Team Rating replay by:

1. map start time;
2. map completion time;
3. `match_id`.

Every update receives the single prediction cutoff. Per-team overlapping map
chronology fails closed as `overlapping_team_match_chronology`.

The target match is rejected from the applied-result manifest. A result that is
available after the producer observation or after the target cutoff is excluded.
The producer also refuses a target that already has any result authority, even
when a caller supplies a nominally pre-cutoff timestamp.

The resulting raw probability is generated by the existing frozen Team Rating
implementation. Its artifact contains ratings, rating difference, roster
continuity, support, state-before hash, authority manifest, rating replay hash,
target manifest, configuration identity, training-input hash, prediction-input
hash, artifact hash, timestamps, and run identity. There are no R.O.S.H., Draft,
Cluster, Player-Hero, odds, or calibration inputs.

## Persistence and replay

Migration `20260807_0032` adds four Team Rating authority ledgers and one explicit
R.O.S.H. dependency-failure ledger:

- `prospective_team_rating_seeds`;
- `prospective_team_rating_authorities`;
- `prospective_team_rating_attempts`;
- `prospective_team_rating_settlements`;
- `prospective_rosh_team_rating_failures`.

The existing reconstructed builder remains unchanged and continues to require
`reconstructed_walk_forward` plus `reconstructed_map_start`. Prospective runs use
the separate `build_prospective_team_rating_storage_records` path. Database
insert guards independently require a prospective trained parent, predicted
child with a NULL outcome, matching target/cutoff/configuration/seed authority,
canonical manifests, exact content hashes, and state snapshots. All five new
tables and the existing Team Rating ledgers reject `UPDATE` and `DELETE`.

An exact retry returns unchanged when its identity and content match. A different
artifact for an already-produced map is an immutable conflict. Team Rating rows,
state snapshots, and the prospective authority row are committed in one outer
transaction, so a failure rolls the entire target back.

Offline exact replay is:

```text
frozen seed state
+ ordered archived result manifest
+ frozen Team Rating configuration
-> state before target
-> Team Rating-only prediction
-> input, state, manifest, artifact and run hashes
```

Changing an artifact, manifest, state hash, or prediction linkage is rejected by
the Python verifier and PostgreSQL insert guards.

## Settlement

Settlement appends a row to `prospective_team_rating_settlements` only after a
formal authoritative result is ready and its artifact hash and availability time
agree with the current result authority. It never updates
`team_rating_predictions`: the original prediction remains `predicted` with
`eventual_radiant_win = NULL`.

## R.O.S.H. shadow linkage

`resolve_rosh_team_rating_authority` exposes only predictions connected to the
new prospective authority ledger. A reconstructed Team Rating prediction cannot
pass this lookup. When no valid P0 exists, the resolver appends:

```text
missing_reason = prospective_team_rating_unavailable
```

to `prospective_rosh_team_rating_failures` and returns no authority, so callers
cannot create a P1-only shadow record. When P0 exists, the existing prospective
R.O.S.H. PostgreSQL guard verifies its run, probability, input hash, training
hash, artifact identity, cutoff, status, and NULL outcome before accepting P1 or
a P0-only missing-R.O.S.H. record.

## One-shot operation

Default scanning covers a 24-hour missed-cutoff lookback and the next 24 hours of
approved formal maps. The lookback creates one stable terminal failure instead
of a post-match P0. Scanning skips maps that already have a prospective authority
or are waiting for a persisted retry:

```powershell
python scripts\run_prospective_team_rating.py `
  --database-url $env:DATABASE_URL `
  --artifact-root dogfood-output\prospective-team-rating-artifacts
```

A bounded map or window can be selected with `--match-id`, `--scan-start`,
`--scan-end`, and `--limit`. `--dry-run` computes and verifies without writing
Team Rating, authority, attempt, or artifact rows.

Seed creation requires the already accepted configuration JSON and an explicit
historical cutoff:

```powershell
python scripts\run_prospective_team_rating.py `
  --database-url $env:DATABASE_URL `
  --freeze-seed-config C:\authority\team-rating-config.json `
  --seed-cutoff 2026-08-07T00:00:00+00:00 `
  --dry-run
```

Removing `--dry-run` freezes the seed after its dry run is reviewed. The config
JSON is the direct `TeamRatingConfig` payload; the command does not select or
modify any field.

## Worker

`scripts/run_prospective_team_rating_worker.py` is independent of the odds and
historical R.O.S.H. workers. It processes at least one target per iteration,
uses content-addressed idempotency for restart recovery, and persists bounded
retry state. Temporary missing authority is retried after 1, 5, and 15 minutes;
retries stop at the cutoff. A missed cutoff is recorded and no post-match P0 is
backfilled.

```powershell
python scripts\run_prospective_team_rating_worker.py `
  --database-url $env:DATABASE_URL `
  --batch-size 5 `
  --poll-seconds 60
```

## Verification

The isolated PostgreSQL suite covers both 20-target and 100-target cohorts plus:

- exact retries and immutable conflicts;
- transaction rollback;
- state snapshot recovery;
- target, future, post-observation, and post-cutoff result exclusion;
- cutoff-missed refusal;
- prospective-only R.O.S.H. authority resolution;
- canonical input, artifact, and state hash guards;
- append-only update/delete rejection;
- independent settlement that leaves the prediction unchanged;
- successful P0 consumption by the existing R.O.S.H. shadow;
- stable `prospective_team_rating_unavailable` recording without P1.

The unit suite also creates 20-result seed evidence and 100 distinct future
targets, checks deterministic repeated replay, and asserts that artifacts contain
no R.O.S.H., Draft, Cluster, or odds inputs.

## Production acceptance boundary

No real source `DATABASE_URL` was available in the implementation workspace, so
this change does not claim that a live 5-10-map collection has already occurred.
After merge and an explicit seed freeze, production acceptance must first be
limited to 5-10 future formal maps. For each map verify that P0 was stored before
cutoff, lineage is complete, legal R.O.S.H. evidence produces paired P1,
missing R.O.S.H. preserves P0-only, and post-match settlement is independent.
These shadow rows remain non-deployment evidence and never create orders.
